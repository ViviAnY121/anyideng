一、项目背景

随着网络购票普及，用户对”价格变动通知”的需求越来越强烈。本项目以机票订购场景为切入点，在实现基础订票功能之外，重点攻克了一个技术难点：

如何在用户不刷新页面的情况下，第一时间感知到航班价格下降？

最终选择了 WebSocket（在线实时弹窗）+ Spring Mail（邮件兜底） 的双通道推送方案。

二、技术选型

层级 技术 选型理由
前端 Vue 3 + Element Plus Composition API 更灵活，组件库成熟
后端 Spring Boot 2.7 快速搭建，生态完善
数据库 MySQL 8 + JPA 关系型数据，ORM 减少 SQL 样板代码
实时推送 WebSocket（JSR-356） 浏览器原生支持，双向通信，无需轮询
邮件通知 Spring Mail + QQ SMTP 配置简单，HTML 模板支持良好
定时任务 Spring @Scheduled 无需引入额外框架，5分钟扫描一次价格
异步处理 Spring @Async 邮件发送不阻塞主线程

七、维护记录

注1：Lombok 在某些 Mac 环境下注解处理器不生效

现象： mvn compile 报大量 找不到符号 错误，所有 getter/setter 和 log 变量均提示未定义。

原因： Lombok 依赖注解处理器（APT）在编译期生成代码，部分 Maven 版本 + JDK 组合下 APT 不会自动启用。

解决方案： 彻底移除 Lombok，改为手写 getter/setter，@Slf4j 改为：

虽然代码量增加，但完全不依赖环境配置，任何 JDK 版本都能编译通过。

注2：@ServerEndpoint 的 Bean 注入问题

现象： WebSocket 端点类里 @Autowired 注入的 Bean 全为 null。

原因： @ServerEndpoint 注册的类不由 Spring 容器管理生命周期，每次新连接都会 new 一个实例，导致依赖注入失效。

解决方案： 将需要的 Service 存为 static 字段，通过 @PostConstruct 或构造器注入：

或者更简单地——把推送逻辑设计成 static 方法，只操作 ConcurrentHashMap，不依赖 Spring Bean。

注3：WebSocket 心跳与 Nginx 超时

现象： 生产环境下 WebSocket 连接约 60 秒后自动断开。

原因： Nginx 默认代理超时为 60 秒，空闲连接会被强制关闭。
